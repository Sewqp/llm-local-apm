# 기존 APM 실검증 기준 자료

정리일: 2026-10-26. 이번 작업은 과거 증거 회수·사본 보존·대조다. 새 부하 테스트, 모델 추론, 파인튜닝은 실행하지 않았다.

## 보존 위치와 해석 규칙

로컬 보존본: `.local-evidence/2026-10-26/`. `manifest.json`에 각 파일의 출처·크기·SHA-256, Git 리비전과 작업 트리 상태, SQLite 무결성·집계를 기록했다. 이 경로는 Git에서 제외한다. 원본 DB·영상·대화에는 로컬 경로와 상세 데이터가 있어 공개 포트폴리오에 그대로 넣지 않는다.

54개 파일을 보존했다. 원본 시연 영상은 파일 무결성 보존 대상이며 이번에 전 구간을 재생·검증한 것은 아니다. 그래프와 로컬 설정은 **현재 상태** 사본이므로 과거 실행 설정으로 소급하지 않는다.

근거의 우선순위는 저장된 관측값·화면·실제 코드, 당시 사용자 확인, 과거 설명·메모 순이다. 당시 AI가 단정한 문장도 검증 결과로 자동 승격하지 않는다. 테스트 서버는 개인 포트폴리오 구현이며 에피드 게임즈의 실제 운영 서버가 아니다.

- 근거: initial 분석 ID 1·3, 초기 README 및 APM 메모리 사본.

### VAL-012 — 0에 가까운 기준선의 정밀도 손실과 모델 오해

- initial ID 2의 실제 기준선은 `0.018916ms`로 양수인데, 모델은 ‘0ms로 설정되어 통계적 비교가 불가능’하다고 설명했다. 이 판단은 저장된 수치와 다르다.

- 다음 평가에서는 소수점 정밀도와 단위를 유지하고, 0·근접한 양수·표본 부족을 구분하게 한다. VAL-003의 탐지 임계값 문제와 별도로 프롬프트·설명 품질 사례로 보존한다.

## 3. 이번 코드 검토로 추가한 과제 — 과거 LLM 발견 실적으로 쓰지 않음

- ApmReporter의 무제한 큐와 한 건씩 HTTP 전송은 대량 수집 시 적체·오버헤드 검증이 필요하다.
- 현재 메트릭은 유저·세션·trace 연결을 제공하지 않는다. 서버 핸들러 시간과 클라이언트 체감 지연은 다르다.
- PacketDispatcher의 타이머 이전에 처리되는 대기/조기 반환과 도메인 실패를 현재 성공·예외 상태만으로 충분히 구분하지 못한다.
- 과거 분석 화면의 스니펫은 저장 당시 코드가 아니라 조회 시점 소스를 다시 읽는다. 리비전과 원본 근거를 보존해야 과거 분석을 정확히 재생할 수 있다.
- 모델이 제시한 경로를 실제 파일로 읽는 흐름은 허용 루트 경계와 접근 권한 검증을 강화할 대상이다. 이번에 침투 테스트를 실행한 것은 아니다.

이들은 [강화 계획](apm-upgrade-plan.md)의 2~4단계 입력이다.
