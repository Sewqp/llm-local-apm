# APM 작업 연속성

최종 갱신: 2026-10-26.

- **최신: 다른 서버 구조 예제를 작성·실행했다.** [예제·재현](../examples/ArchitectureDemo/README.md), [결과·제한](apm-architectures-20261026.md). 순차/병렬 HTTP, 별도 Stock 프로세스 호출, bounded Channel 워커. 각 부하 경로 320/320 성공(동시 HTTP 32), 진입/metric 1,406건, span 8,860개 대조. 큐 65건 중 9접수/56제한, 8완료/1주입 실패. 기존 게임의 3만 동접과 다른 합성 검증이다.
- HTTP 상태·경로, 분산 부모 연결, 별도 작업 trace와 접수 요청 link, 다중 서비스 코드 근거 및 서비스별 수집 UI 추가. 구조 검사 58 + Agent 33 + API 30 + 경로 5 통과. 기존 v2 DB 사본의 span 23,240개 등 기존 열 내용과 보존 원본 불변. 첫 타임스탬프 검증 스크립트 오류도 보존했다.
- 로컬 Gemma 최종 조사 약 9.12초/6.62초. 첫 워커 답변의 로그 span 오인용과 재실행 답변 모두 보존. 정량 정확도나 파인튜닝 성과가 아니다. 증거: `.local-evidence/2026-10-26-architectures/manifest.json`.
- 새 수집 서버 5239, Edge 5241, Stock 5242는 별도 DB로 실행 중. 실행 파일·PID·Run ID는 새 증거의 processes.json 및 collector-final.pid 참조. 기존 5229 수집기와 게임은 유지했다. 아래 과거 3만 검증의 실패·장애 내성 한계도 여전히 유효하다.

- **최신: 수집 신뢰성 개선 후 3만 동접 재검증 완료.** [결과·중간 실패·수집 정책](apm-reliability-20261026.md)를 우선 확인한다. 최종 `reliability-30000-20261026T111916Z`에서 30,000 동접 60.0024초 유지, 로그인 30,000건·Heartbeat 414,969건을 전량 수집했다. 기본/상세 전송 유실 0, HTTP 실패 0. 정상 상세 1% 선택과 64구간 상한은 별개이며 모든 내부 구간 전량 수집이라고 주장하지 않는다.
- 기본 요청/상세 큐와 자원 전송을 분리하고, 늦은 Redis span, 도착 순서 역전, prepared SQLite 배치 저장, 중복 인덱스, FULL 내구성을 유지한 WAL/캐시, 상세 묶음 전송 조건과 순간 부하 예산을 개선했다. 상세/기본 큐 각 32,768, 배치 256. 중간 42,724개 기본 유실과 798/6,300개 상세 유실 결과도 별도로 보존했다.
- **남은 장애 내성 한계:** 최종과 같은 코드의 직전 4차 실행은 런타임 정체 8.619초·6.114초와 함께 기본 3,154건 유실, HTTP 실패 시도 3회를 기록했다. GC pause는 해당 로그상 0이며 정체의 원인은 미확정이다. 최종 무손실 실행만으로 반복 무손실·장애 복구를 보장하지 않는다. 영속 재전송과 정체 원인 조사가 다음 과제다.
- 최종 회귀 25 Agent + 25 API + 19 게임 항목 통과. 원본 DB 사본 2개 마이그레이션에서 과거 1,192,179 metric/20 analysis의 행 내용과 원본 파일 불변을 재확인했다. 로컬 Gemma 복구 후 새 주입 오류 분석 12.063초 완료. 답변은 권한 예외를 설명했으나 재화 지급 후 검사라는 핵심 순서를 명확히 찾지 못했으므로 정확도 성공으로 분류하지 않는다.
- 새 비공개 증거 `.local-evidence/2026-10-26-reliability/manifest.json`. 기존 원본 DB와 모든 이전 증거를 유지한다. 아래 항목은 이전 시점의 이력이다.


- **이전: 19시대 실제 3만 동접 검증.** [동접 검증 결과](concurrency-validation-20261026.md)를 우선 확인한다. 서버는 30,000 동시 로그인 60.0116초 유지, 접속/로그인 실패 및 비정상 종료 0, Heartbeat 417,615/417,615 응답. OS TCP와 APM 세션 수에서도 30,000을 확인했다.
- **APM 전량 수집은 실패했다.** 3만 실행에서 로그인 6,089/30,000(20.30%), Heartbeat 105,806/417,615(25.34%)만 저장됐다. 공유 큐 포화로 누적 3,323,634 telemetry 항목 유실을 기록했다. 요청 실패 수와 혼동하지 않는다. 이전 800건 검증의 무손실 결과를 3만 규모에 확대하지 않는다.
- 새 증거 `.local-evidence/2026-10-26-concurrency/manifest.json`; Run ID는 본문 참조. 이후 우선순위는 집계/자원과 trace 큐 분리, 명시적 trace 선택 수집, 배치 저장 처리율 검증이다. 이 동접 요청에서는 수집 정책을 수정하지 않았다. 아래 ‘3만 재검증 전’ 기록은 이전 v2 완료 시점의 이력이다.

- 사용자가 에피드 게임즈 AI 운영관리 공고에 맞춘 로컬 LLM APM 강화 계획을 승인하고, 계획 저장과 1단계 착수를 요청했다.
- 최신 계획: [apm-upgrade-plan.md](apm-upgrade-plan.md).
- 실제 검증·발견·실패·누락: [validation-baseline.md](validation-baseline.md).
- 평가 사례 목록: [evaluation/cases.json](evaluation/cases.json). 아직 평가 실행 결과나 학습 데이터셋이 아니다.
- 비공개 원본 보존본: `.local-evidence/2026-10-26/manifest.json`. DB 2개, 메트릭 1,192,179행, 분석 20행과 관련 증거. Git 제외 상태를 유지한다.
- 2026-10-26 후속 요청으로 당일 실제 APM 기능 구현까지 승인받아 v2를 구현했다. [변경·실측 결과](apm-v2-20261026.md), [실행 안내](apm-v2-runbook.md)를 먼저 읽는다. 요청·DB/Redis/Grain 추적, 가명 유저 조회, 오류/자원, 수집 상태, 근거 스냅샷을 보존하는 로컬 LLM 조사를 구현했다.
- 새 검증: Agent 15/15, API 16/16, 실제 게임 통합 19/19, 기존 DB 사본 2개 마이그레이션 통과. 16 TCP 연결의 Heartbeat 응답/수집 800/800, 의도적 DB 잠금 약 800ms가 DB span 810.354ms로 관측됐다. 과거 3만 동접을 다시 검증한 것은 아니다.
- 로컬 Gemma로 동일 DebugHandler 주입 오류를 두 번 조사했다. 현재 코드를 함께 제공한 실행에서 권한 검사 순서 문제를 지적했다. 코드 주석에 의도적 오류 설명이 있고 로그 오인용도 있었으므로 일반화된 정확도나 파인튜닝 효과를 주장하지 않는다. 새 학습은 수행하지 않았다.
- 새 비공개 증거: `.local-evidence/2026-10-26-upgrade/manifest.json`. 기존 54개 보존본 및 평가 목록 12개와 별도 유지. 원래 DB 2개의 원본 파일 해시는 불변이다.
- 범위: 로컬 포트폴리오용 APM v2와 실증 완료. 전체 6단계 계획이나 상용 APM과의 동등성 완료가 아니다. 다음은 고정 사례 회귀 평가, Graphify 캐시 버전 관리, 도구 감사 기록, 분산 경로 검증, 수집 오버헤드 비교와 운영 기능이다. 파인튜닝은 검수 자료가 쌓인 뒤 수행한다.
- HeartbeatManager 실제 순차 호출 구조를 유지한다. 과거 Task.WhenAll 변경은 개선 미입증으로 원복했다. 기존 성공 화면의 분석 모드는 quick이다.
- DebugHandler는 의도적으로 넣은 오류 검증 사례다. 과거 실수집 지표와 섞어 자연 발생 사고로 표현하지 않는다.
- APM 컨트롤러 및 대상 서버에 기존 미커밋 변경이 있다. 과거 HEAD만으로 작업 상태를 대신하거나 덮어쓰지 않는다.
- 핵심 의도: 코드·상세 로그·유저별 흐름을 내부 LLM과 연결한다. 로컬 실행만으로 유출 위험 0을 보장하지 않고 실제 데이터 경로와 접근·송신 통제를 검증한다.

기존 개인 메모리에는 이 계획의 요약과 포인터를 추가했다. 과거 초기 메모가 최신 기록과 다르면 날짜와 실제 증거를 먼저 확인한다.
